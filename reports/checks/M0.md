## What runs

GitHub Actions runs `smax tick` every hour at :07 UTC (`.github/workflows/tick.yml`). Each run collects:

| Source | What | How often | Why it cannot wait |
| --- | --- | --- | --- |
| Open-Meteo Single Runs | Every archived run of the 8 models (UTC, 8 days ahead) | as each run appears | — (archived by Open-Meteo; ours is the copy we used) |
| Open-Meteo open-data bucket | When each run was published (`latest.json`, run folders) | hourly + daily listing | gives honest availability times |
| NOAA Aviation Weather Center | Airport reports with receipt times | hourly | — |
| IEM | Airport reports, archive of record | daily | — |
| KNMI | Official daily maximum TX/TXH | daily | — |
| DWD MOSMIX_L 06240 | Ready-made corrected forecast (benchmark) | every new run | DWD keeps ~2 days |
| Open-Meteo Ensemble | ECMWF ensemble, Schiphol only (later add-ons) | daily | the API keeps ~3 days |

Raw responses are write-once (A3); `smax rebuild` recreates every derived table (A3). All timestamps are UTC;
the target day is built with the Europe/Amsterdam time zone (A5).

## Completeness and alerts (A6)

- `reports/completeness/YYYY-MM-DD.md` each morning lists:
  - every expected model run, split into stored, not in the archive, and never fetched;
  - the airport-report count;
  - the MOSMIX runs;
  - the latest KNMI day;
  - every scheduled forecast run.
- A source that fails twice in a row raises an alert. So do any job failure, any problem in the completeness report, and a re-run mismatch.
- Every alert fails the GitHub run, which emails the owner. An optional healthchecks.io secret also gets a heartbeat, so a job that stops running is noticed too.
